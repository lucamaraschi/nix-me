# BETA-006 protected macOS release credentials

Date: 2026-10-13

## Configured

- GitHub environment: `macos-beta-release`
- Deployment policy: tags matching `v*-*`
- Environment secret: `SPARKLE_PRIVATE_KEY`
- The repository-level Sparkle secret was removed after the environment copy
  was verified, so unrelated workflows can no longer request it.
- Release workflow selects `macos-beta-release` for prereleases and
  `macos-stable-release` for stable versions.
- Secrets are scoped to only the workflow steps that consume them.
- Signing certificate files and the temporary keychain are removed on every
  workflow outcome.
- Concurrent publication of the same release tag is disabled.

The environment configuration is reproducible with
`tools/release/configure-beta-environment.sh`. Its readiness can be checked
without reading secret values with
`tools/release/check-macos-release-readiness.sh macos-beta-release`.

## Why this gate is parked

The repository-side work is complete, but this Mac has only Apple Development
identities. It has neither the Developer ID Application identity required to
distribute outside the Mac App Store nor an App Store Connect team API key for
notarization. These credentials must be created by an authorized Apple account
holder; they cannot be derived from repository data.

The following environment secrets remain missing:

- `CERTIFICATE_P12_BASE64`
- `CERTIFICATE_PASSWORD`
- `APPLE_API_KEY_ID`
- `APPLE_API_ISSUER_ID`
- `APPLE_API_PRIVATE_KEY_BASE64`

Do not configure them as repository secrets. Keep them scoped to the
`macos-beta-release` environment.

## Operator prerequisites

The operator needs:

- Account Holder access to the Apple Developer Program to create a Developer ID
  certificate. Apple permits up to five active Developer ID Application
  certificates per account.
- Account Holder or Admin access in App Store Connect to create a team API key.
  If App Store Connect API access has never been enabled for the team, the
  Account Holder must request it first.
- Admin access to `lucamaraschi/nix-me` GitHub environments and secrets.
- GitHub CLI authenticated for that repository: `gh auth status`.

Use a team App Store Connect API key. Apple's `notarytool` does not support
individual API keys. Assign the least-privileged team role allowed by the
organization's release policy, and never reuse a personal key.

## 1. Create the signing identity

1. On a trusted Mac, open **Keychain Access > Certificate Assistant > Request a
   Certificate From a Certificate Authority**.
2. Enter the Apple Developer account email and a descriptive common name, leave
   the CA email blank, select **Saved to disk**, and save the CSR.
3. Sign in to Apple Developer **Certificates, Identifiers & Profiles**, create a
   **Developer ID Application** certificate, and upload that CSR. Do not choose
   **Apple Development** or **Developer ID Installer**. Select the G2
   intermediate certificate if Apple presents that choice.
4. Download and open the resulting `.cer` on the same Mac that created the CSR.
   In Keychain Access under **My Certificates**, confirm that the certificate
   expands to show its private key.
5. Verify that macOS recognizes the identity:

   ```bash
   security find-identity -v -p codesigning \
     | grep 'Developer ID Application:'
   ```

6. In **My Certificates**, select the Developer ID Application certificate and
   its private key together, export them as `DeveloperIDApplication.p12`, and
   protect the export with a new strong password. The exported file must include
   the private key; exporting only the public certificate will make signing fail.

References:

- [Create Developer ID certificates](https://developer.apple.com/help/account/certificates/create-developer-id-certificates/)
- [Create a certificate signing request](https://developer.apple.com/help/account/certificates/create-a-certificate-signing-request/)
- [Replace or create G2 Developer ID certificates](https://developer.apple.com/help/account/certificates/replace-developer-id-certificates/)

## 2. Create the notarization key

1. In App Store Connect, open **Users and Access > Integrations > App Store
   Connect API**.
2. Select **Team Keys**, generate a key for the Nix-Me release workflow, and
   record its **Key ID** and the team's **Issuer ID**.
3. Download `AuthKey_<KEY_ID>.p8`. Apple allows the private key to be downloaded
   only once. Store it in the team's credential vault before continuing.
4. If the file, key ID, or issuer ID is exposed, revoke the key immediately and
   create a replacement. Never paste the `.p8` contents into chat, email, an
   issue, or a shell command argument.

References:

- [App Store Connect API access](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/)
- [Create App Store Connect API keys](https://developer.apple.com/documentation/AppStoreConnectAPI/creating-api-keys-for-app-store-connect-api)
- [`notarytool` API-key requirements](https://developer.apple.com/documentation/technotes/tn3147-migrating-to-the-latest-notarization-tool)

## 3. Upload the environment secrets

Run these commands from a private terminal. Replace only the two local file
paths and the key/issuer values. Secret values are passed over standard input so
they do not appear in shell history or process arguments.

```bash
cd /path/to/nix-me

export GITHUB_REPOSITORY=lucamaraschi/nix-me
export RELEASE_ENVIRONMENT=macos-beta-release

base64 < /secure/path/DeveloperIDApplication.p12 \
  | gh secret set CERTIFICATE_P12_BASE64 \
      --repo "$GITHUB_REPOSITORY" --env "$RELEASE_ENVIRONMENT"

read -r -s -p 'P12 export password: ' CERTIFICATE_PASSWORD; echo
printf '%s' "$CERTIFICATE_PASSWORD" \
  | gh secret set CERTIFICATE_PASSWORD \
      --repo "$GITHUB_REPOSITORY" --env "$RELEASE_ENVIRONMENT"
unset CERTIFICATE_PASSWORD

printf '%s' 'REPLACE_WITH_KEY_ID' \
  | gh secret set APPLE_API_KEY_ID \
      --repo "$GITHUB_REPOSITORY" --env "$RELEASE_ENVIRONMENT"

printf '%s' 'REPLACE_WITH_ISSUER_ID' \
  | gh secret set APPLE_API_ISSUER_ID \
      --repo "$GITHUB_REPOSITORY" --env "$RELEASE_ENVIRONMENT"

base64 < /secure/path/AuthKey_KEYID.p8 \
  | gh secret set APPLE_API_PRIVATE_KEY_BASE64 \
      --repo "$GITHUB_REPOSITORY" --env "$RELEASE_ENVIRONMENT"

unset RELEASE_ENVIRONMENT GITHUB_REPOSITORY
```

The source `.p12`, its password, and the `.p8` must remain in the approved team
credential vault until replacement or revocation. Delete working copies from
Downloads and other temporary locations after the vault copy and GitHub upload
have both been verified.

## 5. Run the beta release trial

Merge the release workflow changes to `main` before tagging. From a clean and
up-to-date `main` checkout, create a prerelease tag with the next unused version:

```bash
git switch main
git pull --ff-only origin main
git status --short
git tag -s v0.2.0-beta.1 -m 'Nix-Me 0.2.0 beta 1'
git push origin v0.2.0-beta.1
gh run list --workflow 'Release macOS App' --limit 5
```

If signed Git tags are not yet operational for the release owner, resolve that
policy before publishing rather than silently creating an unsigned production
tag. Do not reuse an existing tag after a failed release; fix the problem and
use the next beta number.

After the workflow succeeds, download the DMG and checksum onto a Mac that did
not build the artifact, then verify them:

```bash
tag=v0.2.0-beta.1
destination="$(mktemp -d)"
gh release download "$tag" --repo lucamaraschi/nix-me --dir "$destination"
cd "$destination"
shasum -a 256 -c Nix-Me-*.dmg.sha256
dmg="$(find . -maxdepth 1 -name 'Nix-Me-*.dmg' -print -quit)"
xcrun stapler validate "$dmg"
spctl --assess --type open --context context:primary-signature --verbose=2 "$dmg"
```

Mount the DMG, copy **Nix Me.app** to `/Applications`, launch it from Finder, and
confirm that Gatekeeper does not show an unidentified-developer or damaged-app
warning. Also confirm that the GitHub release is marked prerelease and that its
appcast entry points to the same version.
