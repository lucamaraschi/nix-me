# BETA-006 protected macOS release credentials

Date: 2026-10-13

## Configured

- GitHub environment: `macos-beta-release`
- Deployment policy: tags matching `v*-*`
- Environment secret: `SPARKLE_PRIVATE_KEY`
- The repository-level Sparkle secret was removed after the environment copy
  was verified, so unrelated workflows can no longer request it.
- Release workflow selects `macos-beta-release` for prereleases and
  `macos-stable-release` for stable versions.
- Secrets are scoped to only the workflow steps that consume them.
- Signing certificate files and the temporary keychain are removed on every
  workflow outcome.
- Concurrent publication of the same release tag is disabled.

The environment configuration is reproducible with
`tools/release/configure-beta-environment.sh`. Its readiness can be checked
without reading secret values with
`tools/release/check-macos-release-readiness.sh macos-beta-release`.

## Required credentials

The following environment secrets are not available on the validation Mac and
must be supplied by an Apple Developer account holder:

- `CERTIFICATE_P12_BASE64`
- `CERTIFICATE_PASSWORD`
- `APPLE_API_KEY_ID`
- `APPLE_API_ISSUER_ID`
- `APPLE_API_PRIVATE_KEY_BASE64`

Do not configure these as repository secrets. The `.p12` must contain a
Developer ID Application identity, not an Apple Development identity. The App
Store Connect key must be authorized for notarization.

## Completion check

After adding the five missing values, run:

```bash
tools/release/check-macos-release-readiness.sh macos-beta-release
```

Then push a prerelease tag such as `v0.2.0-beta.1`. BETA-006 is complete when
the workflow publishes a Developer ID signed, notarized, and stapled DMG whose
Gatekeeper assessment passes on a clean Mac.
