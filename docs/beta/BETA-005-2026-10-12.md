# BETA-005 disposable macOS validation

Date: 2026-10-12

## Environment

- Disposable UTM clone of a macOS 26.1 arm64 base image
- Fresh nix-me checkout with the `beta.nix` profile enabled
- Determinate Nix 2.35.2
- VM-only install overrides: `SKIP_XCODE_CLT=1`, `SKIP_BREW_ON_VM=1`, and
  `SKIP_MAS_APPS=1`

The base VM was not modified. The disposable clone had no Xcode Command Line
Tools or Homebrew, so GNU Make was provided temporarily with
`nix shell github:NixOS/nixpkgs/nixpkgs-25.05-darwin#gnumake`.

## Results

| Check | Result | Evidence |
|---|---|---|
| Missing Command Line Tools handling | Pass | Non-interactive installation now exits with an actionable error instead of waiting indefinitely. VM validation can explicitly skip this prerequisite. |
| Fresh Nix installation | Pass | Determinate Nix installed and was detected after its profile was sourced. |
| First system activation | Pass | nix-darwin and Home Manager activated; Node 26.11.1, `nix-me`, `nix-me-apps`, and the post-install TUI were installed. |
| Disposable VM application skips | Pass | Homebrew and Mac App Store activation were disabled without using removed nix-darwin options. |
| `/etc` migration | Pass | nix-darwin created `/etc/static` as a symlink and installed `/etc/nix-me/manifest.json`. Original shell-file backups remained byte-identical across repeat activation. |
| Repeat apply | Pass | A clean Git checkout completed `make switch-fast` in 7.47 seconds. Application-state convergence reported zero drift. |
| Management snapshot | Pass | Schema version 1, clean Git state, matching desired/applied source identities, available application-state engine, and zero application drift. |
| Native app package and signature | Pass | The app built on the host, copied to `~/Applications/Nix Me.app` in the VM, passed `codesign --verify --deep --strict`, and started its `NixMeApp` process. |
| Visual first launch and manual refresh | Blocked | The VM display became unavailable during launch. After reboot, the cloned account required an unknown local login password. No credential was reset, so visual UI validation was not claimed. |

## Defects found and corrected

- The installer could wait forever for the graphical Command Line Tools
  installer during unattended execution.
- An existing Nix installation was missed when its profile had not been
  sourced by the current shell.
- The VM switch recipe passed the rebuild command to `echo` because of a
  missing command terminator and referenced a nonexistent `vm-fix.nix`.
- The removed `homebrew.skipMasApps` option prevented current nix-darwin from
  evaluating VM mode.
- Creating `/etc/static` as a directory prevented nix-darwin from installing
  its required symlink.
- Repeat activation replaced the original `/etc` backups instead of preserving
  them.
- Non-interactive prompts still attempted to read standard input.
- CLI-generated hosts explicitly disabled the application-state engine,
  overriding the beta profile.
- The management API evaluated the environment-driven flake without
  `--impure`, producing a false pending state for dynamic hosts.

## Follow-up

known. Confirm the dashboard renders, refresh completes, and the configuration
and application-state indicators match the recorded API snapshot. This is a
manual visual check; it does not invalidate the successful installation and
