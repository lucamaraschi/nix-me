# AUT-006: T3 evidence dispatch

## Current state

The Rectangle and Raycast procedures, interactive runner, evidence finalizer,
and unsigned stamp-candidate generator are ready. The repository currently has
no registered self-hosted Actions runner, so no honest visible-behavior run can
be dispatched yet. AUT-006 remains `Ready for operator`, not `Done`.

This gate is independent of Apple application notarization. It uses an operator
SSH signing key only after evidence review; that private key must never be added
to GitHub Actions.

## Runner requirements

Register a dedicated Mac as a repository Actions runner with all four labels:

- `self-hosted`
- `macOS`
- `ARM64`
- `utm`

GitHub adds the first three labels automatically for an Apple Silicon Mac; add
`utm` during configuration. Because this is a public repository, use a
short-lived runner dedicated to these two runs. Do not install it as a service,
do not give it repository or cloud credentials, and remove its registration
after both evidence artifacts have been collected.

1. Open the repository's **Settings > Actions > Runners**, choose **New
   self-hosted runner**, then select **macOS** and **ARM64**.
2. In a new dedicated directory on the UTM Mac, run the download, checksum, and
   extraction commands generated by GitHub. Registration tokens expire, so use
   the current commands from the settings page rather than saving them.
3. Run GitHub's generated `config.sh` command with `--labels utm` appended.
4. Start the runner interactively with `./run.sh` under the same logged-in user
   who can open UTM. Keep that terminal open and use a second Terminal window
   for the generated T3 operator command.
5. Confirm that the runner is online and has the expected labels:

   ```bash
   gh api repos/lucamaraschi/nix-me/actions/runners \
     --jq '.runners[] | {name,status,labels:[.labels[].name]}'
   ```

The runner account must have a logged-in graphical session, UTM installed at
`/Applications/UTM.app`, and a clean macOS base VM. The VM must have SSH enabled,
a known account with passwordless sudo, enough disk for a disposable clone, and
working network access. The operator must also have local Terminal access to the
runner while the job is active; GitHub Actions itself cannot answer the visual
challenge.

`Application T3 evidence` is dispatch-only, has read-only repository permission,
and never runs for pull requests. This narrow workflow reduces exposure but does
not make a persistent public-repository runner safe. See GitHub's
[runner registration](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners),
[label](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/apply-labels),
and [secure-use](https://docs.github.com/en/actions/reference/security/secure-use)
guidance.

## Dispatch both runs

After this workflow is merged to `main`, replace the base VM and user values if
needed, then dispatch one run per procedure:

```bash
gh workflow run t3-app-state.yml --repo lucamaraschi/nix-me --ref main \
  -f procedure=rectangle-visible-window-management \
  -f 'base_vm=macOS-base' \
  -f vm_user=admin

gh workflow run t3-app-state.yml --repo lucamaraschi/nix-me --ref main \
  -f procedure=raycast-generated-import \
  -f 'base_vm=macOS-base' \
  -f vm_user=admin
```

Each job stages a revision-bound request and prints one command. Open Terminal
on that exact runner and execute the printed `run-t3.sh` path. Keep the UTM
display visible, perform the procedure yourself, capture only the clean VM, and
enter the requested observation and challenge. Treat the screenshot or video as
future public repository evidence and exclude personal or secret information.

The job waits for at most two hours. On success it revalidates the draft,
creates `stamp-candidate.json`, and uploads the run directory and diagnostics as
an Actions artifact retained for 30 days. The candidate explicitly has
`stamp_eligible: false`; it is a deterministic preview, not verification.

## Review and production signature

Download each artifact into the same repository-relative `evidence/runs/`
location recorded by its draft manifest. Review the image or video, observation,
apply output, and idempotence output before finalizing:

```bash
RUN_DIR=packages/app-state/evidence/runs/REPORTED_RUN_ID
RECIPE_ID=rectangle # use raycast for the Raycast run

packages/app-state/evidence/tools/t3-procedure collect-draft "$RUN_DIR"
jq . "$RUN_DIR/stamp-candidate.json"
mkdir -p packages/app-state/evidence/manifests
packages/app-state/evidence/tools/t3-procedure finalize \
  "$RUN_DIR" "packages/app-state/evidence/manifests/$RECIPE_ID.json"
```

Confirm that the canonical SHA-256 of the finalized manifest matches
`prospective_final_manifest_sha256` in the candidate:

```bash
jq -cS . "packages/app-state/evidence/manifests/$RECIPE_ID.json" \
  | shasum -a 256
```

Only an explicitly enrolled human operator may then sign and stamp:

```bash
ssh-keygen -Y sign \
  -f "$T3_SIGNING_KEY" \
  -n nix-me-t3-evidence-v1 \
  "packages/app-state/evidence/manifests/$RECIPE_ID.json"

packages/app-state/evidence/tools/evidence-tool generate-stamp \
  "packages/app-state/evidence/manifests/$RECIPE_ID.json" \
  "packages/app-state/recipes/$RECIPE_ID.yaml"

packages/app-state/evidence/tools/evidence-tool stamp-recipe \
  "packages/app-state/evidence/manifests/$RECIPE_ID.json" \
  "packages/app-state/recipes/$RECIPE_ID.yaml"
```

AUT-006 is complete only after both finalized manifests, signatures, retained
run directories, and recipe stamps are committed and
`packages/app-state/evidence/tools/evidence-tool verify-repository` passes.
Production `.mov` and `.mp4` evidence is tracked with Git LFS; run `git lfs pull`
before repository verification if a checkout contains only pointer files.

After both artifacts are safely downloaded, stop `./run.sh` and remove the
runner from **Settings > Actions > Runners**. Delete its dedicated runner work
directory after GitHub confirms deregistration.
